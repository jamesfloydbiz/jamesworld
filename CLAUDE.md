# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**jamesfloyds.world** — James Floyd's personal site. Pure HTML/CSS/vanilla-JS. No framework. No build step for the pages themselves. Bun is used only for the deploy pipeline (3 small scripts). Hosted on GitHub Pages via `.github/workflows/deploy.yml`.

This codebase was migrated out of a React/Vite/Tailwind SPA in phases ending at commit `d398bc8`. Anything that smells like prerender hacks, JSX, or framework state is either leftover for context (e.g. comments in `scripts/routes.config.mjs`) or actively dead — don't reintroduce it without a strong reason.

## Common commands

```sh
bun run serve:site     # local dev server at http://localhost:3000
                       # merges site/ + public/, no rebuild needed — edit + reload
bun run build:site     # full production build → dist/ (fetches Substack, copies trees, writes sitemap)
bun run fetch:substack # just refresh public/data/substack-posts.json
```

There are no tests, no linter, no typechecker. There's no `npm install` step — `package.json` lists zero runtime/dev dependencies. The 447 MB `node_modules/` is vestigial from the old React stack and can be deleted safely; nothing in the build needs it.

## Architecture

### File layout

```
site/                  ← one index.html per route (the source of truth)
  index.html           ← home (the "Dear Reader" letter)
  sonder/index.html    ← only page with significant inline JS (typewriter reveal + audio)
  writing/index.html   ← runtime-fetches /data/substack-posts.json for the post list
  …/index.html         ← every other route
  404.html             ← noindex'd 404
  css/site.css         ← single shared stylesheet (CSS custom properties, no preprocessor)
  js/site.js           ← shared nav toggle + modal helpers, ~150 lines, no deps

public/                ← static assets, copied first into dist/
  data/substack-posts.json   ← generated by fetch-substack.mjs
  sonder/              ← 12 letter images (.jpg), episode thumbnails, typewriter.mp3
  pictures/, poems/, logos/, images/, models/, ops-images/
  favicon.ico, apple-touch-icon.png, logo.svg, logo.png
  robots.txt, llms.txt
  404.html             ← duplicate of site/404.html for GitHub Pages fallback

scripts/
  build-site.mjs       ← copy public → dist, copy site → dist, write sitemap
  fetch-substack.mjs   ← regex-parse https://jamesfloyd.substack.com/feed → JSON
  serve-site.mjs       ← Bun.serve() dev server, port 3000
  routes.config.mjs    ← single source of truth for sitemap routes
                         (only ROUTES + SITE_URL are still used; the wrap()/
                          FALLBACK_STYLE / .body fields are dead prerender
                          leftovers — safe to clean up, see "Known dead code")

dist/                  ← build output, deployed to GitHub Pages
ideas/ai-search.md     ← spec for a future AI chat over James's corpus
supabase/              ← prior search/chat Edge Functions, parked for ai-search
```

### Build → deploy flow

1. **Edit** a file in `site/`. Reload `http://localhost:3000`. That's the entire dev loop.
2. **`bun run build:site`** runs in order: fetch Substack RSS → write `public/data/substack-posts.json` → wipe and recreate `dist/` → copy `public/` then `site/` (site wins on conflicts) → write `dist/sitemap.xml` from `ROUTES` in `scripts/routes.config.mjs`.
3. **Deploy** is automatic. `.github/workflows/deploy.yml` runs on push to `main`, daily at 06:17 UTC (to pick up new Substack posts), and on-demand via `workflow_dispatch`. Uses `oven-sh/setup-bun@v2`. No `npm install`.

### Per-page interactivity (only what's not pure static)

| Page | What needs JS |
|---|---|
| `/sonder/` | Inline `<script>` runs a typewriter reveal of the 12 letter images (preload + decode then stagger `.revealed` class), plus an `<audio>` click track. Largest interactive surface on the site. |
| `/writing/` | `fetch('/data/substack-posts.json')` on page load → renders post cards → click opens modal with full post HTML. Substack stays the canonical source. |
| `/poems/`, `/builds/` | Modal lightbox per item (via `site/js/site.js` helpers) |
| `/blueprints/mental-models/` | Tab switcher |
| All pages | Nav menu open/close (shared `site/js/site.js`) |

Everything else is plain HTML + CSS.

### SEO surface

- Each route has its own `<title>`, `<meta description>`, `<link rel="canonical">`, OpenGraph, Twitter Card, and (where useful) JSON-LD inline. No central injection — edit each `site/<route>/index.html` directly.
- `sitemap.xml` is generated from `ROUTES` in `scripts/routes.config.mjs`. When you add a new route directory under `site/`, add a corresponding entry to `ROUTES` (only the `path`, `priority`, `changefreq` fields matter now — everything else is dead).
- `public/robots.txt` allows all major search engines and AI crawlers (GPTBot, ClaudeBot, PerplexityBot, etc.).
- `public/llms.txt` is the long-form description used by some LLM crawlers.
- All canonical / sitemap URLs use **trailing slashes** (e.g., `/sonder/` not `/sonder`). GitHub Pages 301-redirects the slashless form, and matching the canonical to the served URL avoids "Redirect error" in Google Search Console.

## Operational gotchas

These have bitten before. Save time:

- **iCloud dataless files.** The repo lives under `~/Library/Mobile Documents/com~apple~CloudDocs/`. Sometimes a file shows in `ls` but `cp`/`mv`/`cat` fail with "No such file or directory" because iCloud hasn't materialized it locally. Fix: `brctl download "<file>"` then retry.
- **macOS screenshot filenames** contain `U+202F` (narrow no-break space) before `AM`/`PM`, not a regular space. Targeting them by literal name in shell will silently fail. Use `find -print0 | xargs -0` or `find . -name "Image *"` (the glob matches the NNBSP).
- **Git author identity.** James can't run `git config` himself. Use a per-command override on every commit: `git -c user.name="James Floyd" -c user.email="249632878+jamesfloydbiz@users.noreply.github.com" commit ...`. Don't try to persist it.
- **Trailing-slash URLs are mandatory** in `<link rel="canonical">`, `<meta property="og:url">`, sitemap `<loc>`, and any internal links to routes. Slashless versions get a 301 from GitHub Pages and Google flags them.
- **`/museum` is gone** as of `af711c6`. The 3D museum lives at `https://jamesworldv2.lovable.app` (a separate Lovable-hosted app). Don't try to add it back.
- **Sonder data is curated.** `site/sonder/index.html` contains the `EPISODE_OVERRIDES` map, `PEOPLE_COUNT`, `PUBLISHED_EPISODES`, location ranges (e.g. `sameLocation(6, 11, 'Central Park')`), and per-letter horizontal offsets. Treat it as data, not code — don't refactor casually.
- **`/writing/` data is live-fetched.** The page reads `/data/substack-posts.json` at runtime. After editing `scripts/fetch-substack.mjs`, run `bun run fetch:substack` so the dev server has fresh data.

## Known dead code (safe to remove)

These are leftovers from earlier stacks. Removing them is fine and arguably overdue:

- `node_modules/` (447 MB) — `package.json` has zero deps, the build uses only Bun/Node built-ins
- `scripts/routes.config.mjs` — the `wrap()` function, `FALLBACK_STYLE` constant, and `body`/`preloadImages` fields on each route are all dead. Only `path`, `priority`, `changefreq`, `SITE_URL` are read by `build-site.mjs`.
- `supabase/` directory — kept as a starting point for the planned AI search feature (`ideas/ai-search.md`); not wired up.

## Style

- Black background, white text. Serif-leaning typography (Playfair Display for display, EB Garamond for body, DM Mono for labels, Lora for the home letter, Space Mono as a fallback). Google Fonts loaded via `<link>` in each page.
- Design tokens live in CSS custom properties at the top of `site/css/site.css` (`--fg-90` through `--fg-12`, surface colors, etc.).
- No Tailwind, no shadcn, no CSS-in-JS.
